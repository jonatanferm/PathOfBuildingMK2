# pob-ui-rust

AREA: crates/pob-ui (lib, ~38.7k Rust lines across 52 src files + 5 WGSL shaders, 558 lines), app/pob-desktop (25-line main.rs), app/pob-web (50-line lib.rs + index.html/Trunk.toml). All UI is immediate-mode egui; there is NO SimpleGraphic-style layer, no bitmap-font code, no TGA/WebP decoding, and no port of PoB's control classes anywhere.

WINDOWING/RENDER STACK (versions from Cargo.lock): eframe 0.29.1 (default-features off; features default_fonts, wgpu, persistence, x11, wayland), egui 0.29.1, egui-wgpu 0.29.1, wgpu 22.1.0 (feature webgl), winit 0.30.13, bytemuck 1, image 0.25.10 (ONLY jpeg+png features), rfd 0.15.4 (native file dialogs), wasm-bindgen 0.2.121, web-sys 0.3.98. Desktop main.rs forces eframe::Renderer::Wgpu (1280x800 window, min 800x600) because the tree uses egui_wgpu paint callbacks. Web lib.rs (#![cfg(wasm32)]) uses eframe::WebRunner on canvas #pob_canvas and FORCES Backends::GL (WebGL2) because wgpu 22's WebGPU path requests the obsolete limit maxInterStageShaderComponents and fails. .cargo/config.toml sets getrandom_backend="wasm_js" for wasm32. Trunk builds index.html -> dist (port 8080); .github/workflows/pages.yml deploys it. All three crates are eframe/egui-bound; the stack is 2 years old relative to today and the wgpu version is the reason WebGPU doesn't work.

TREE RENDERING: crates/pob-ui/src/tree_renderer.rs (1438 lines) + tree_view.rs (1289) + tree_layout.rs (67, node position math from PassiveTree.lua:828-833 / CalcOrbitAngles). TreeRenderer::install(render_state, AtlasInputs) builds 5 wgpu RenderPipelines (node, edge, arc, group, frame; ascendancy reuses the group pipeline with another bind group), uploads 6 atlases as Rgba8UnormSrgb textures (upload_atlas()), one shared uniform buffer (viewport_center, zoom, viewport_size, pixels_per_point), and per-kind growable instance buffers (ensure_*_capacity). It stores itself in egui_wgpu::CallbackResources; each frame tree_view.rs adds 6 egui_wgpu::Callback::new_paint_callback(...) entries (TreeGroupCallback, TreeAscendancyCallback, TreeEdgeCallback, TreeArcCallback, TreeNodeCallback, TreeFrameCallback) that implement CallbackTrait prepare() (write buffers, and it recreates the bind group EVERY frame) and paint() (draw 0..6 instanced). Instance structs (#[repr(C)] Pod): NodeInstance{world_pos,world_radius,kind,state,icon_uv}, EdgeInstance{a,b,state}, ArcInstance{center,radius,angle_a,angle_b,state}, GroupInstance{world_pos,world_size,uv_rect} (FrameInstance/AscendancyInstance are aliases). Shaders: tree_groups.wgsl/tree_frames.wgsl (72/71 lines) are a plain instanced textured quad (corner table, world->NDC, uv_rect remap, alpha-discard) — the closest thing to SimpleGraphic DrawImage, but with no tint color, no arbitrary quad, no per-vertex UV. tree_nodes.wgsl (192) is an SDF circle with state bits (allocated/search/hover/path) and icon sampling from active/inactive/mastery atlases; tree_edges.wgsl (99) and tree_arcs.wgsl (124, tessellated in VS) draw PROCEDURAL lines/arcs — PoB instead draws LineConnector*/Orbit*{Normal,Intermediate,Active} textures with DrawImageQuad, so visuals are NOT PoB-faithful. Search/hover halos, cluster overlays, heatmap badges, tooltips are drawn with egui's CPU painter (painter.circle_stroke, etc.). Approach is not PoB's PassiveTreeView.lua draw order; it is a bespoke renderer.

QUALITY ASSESSMENT: Code is clean, heavily doc-commented with issue refs, and well unit-tested at the pure-logic level, but architecturally it is an egui re-imagining of PoB, not a port. The wgpu tree renderer is competent but special-purpose (fixed pipelines per primitive, SDF nodes, procedural edges, single tree version, prebuilt custom atlases) and is tightly coupled to egui_wgpu CallbackTrait. For a SimpleGraphic-API renderer the reusable parts are patterns, not modules: atlas upload, instanced quad VS/world->NDC math, Pod instance structs, growable buffers, desktop+wasm boot code, wasm getrandom/WebGL workaround. Recommend a fresh crate (winit 0.30 + wgpu >= 24/25 directly, dropping eframe/egui; or keep eframe only as host and draw one full-window paint callback) with: texture cache keyed by path (png/jpg/webp/tga, CLAMP/MIPMAP/NEAREST samplers, async loading), one dynamic vertex buffer of tinted textured quads (4 arbitrary positions + 4 UVs + RGBA + texture/array layer), draw commands bucketed by (layer, subLayer) with stable insertion order, per-command scissor+translate from SetViewport, 3 blend states, and a TGF/TGA bitmap font module with ^-escape color handling.

## risks
- wgpu 22 WebGPU path is broken in current browsers (requests maxInterStageShaderComponents); web build forced to WebGL2 (app/pob-web/src/lib.rs). A new renderer should bump wgpu (and drop/upgrade eframe 0.29 which pins egui-wgpu/wgpu 22) — WebGL2 also lacks some features (e.g. limited texture array sizes, no storage buffers in VS) so design the quad batcher to WebGL2 limits.
- image crate is built with only jpeg+png features: PoB needs webp (TreeData/3_28+, 32 files) and tga (all bitmap fonts). Add features or a dedicated TGA reader; check TGA variants (RLE, 8-bit alpha-only) used by SimpleGraphic fonts.
- PLAUSIBLE colour-space bug: atlases are uploaded as Rgba8UnormSrgb (tree_renderer.rs upload_atlas) while egui-wgpu 0.29 prefers a non-sRGB framebuffer; sampling linearises and the shader writes linear values to a gamma target, darkening icons. SimpleGraphic (OpenGL) blends in gamma space with non-sRGB textures; a faithful port should use Rgba8Unorm textures + non-sRGB surface (or match explicitly) to reproduce PoB colours.
- Sprites are hardcoded to tree 3_25 (data/sprites/3_25*, include_bytes! on wasm) while PoB ships 2_6..3_29 incl. ruthless/alternate variants; the custom pre-composited group-background.png is not PoB's asset. Not reusable as-is for a version-aware PassiveTreeView port.
- Wasm bundles assets via include_bytes! (bloats .wasm); PoB's ~25MB+ of TreeData/Assets plus 112 font TGAs need an HTTP/fetch-based async asset loader on web (maps naturally onto SimpleGraphic's ASYNC/IsLoading semantics).
- Tree edges/arcs are procedural (SDF lines, tessellated arcs) rather than PoB's LineConnector*/Orbit* textures via DrawImageQuad; node visuals are SDF circles — visually diverges from PoB, so tree_renderer shaders should not be the basis of a parity renderer.
- lib.rs is a 6159-line god-module with ~80 LoadedApp fields and both native (PoB worker) and wasm (pob_engine) calc paths interleaved via cfg; untangling is impractical — treat pob-ui as a parts bin, start a new UI crate.
- All pob_* panels (controls, items, calcs, config, skills, party, sets, sidebar, tooltip, popup) are thin egui mirrors of live Lua state via __mk2_* hooks; none contain the underlying logic — the Rust ports must reimplement PoB's Classes/*Control.lua, *Tab.lua, Tooltip.lua, PopupDialog.lua from Lua source, not from these files.
- Networking host code that matters most (DownloadPage HTTP, OAuth redirect listener, OpenURL) lives in crates/pob-calc/src/jit.rs bound to mlua; it must be extracted before pob-calc is reduced to a test oracle. ureq is blocking and native-only; wasm needs a fetch-based equivalent and will hit CORS on pathofexile.com, trade API and most build sites (documented in ggg_fetch_wasm.rs) — OAuth localhost redirect is impossible on web.
- egui provided clipboard, IME/text input, DPI scaling, keyboard/mouse mapping and native file dialogs (rfd); dropping eframe means re-implementing these against winit (PoB needs Copy/Paste, IsKeyDown, GetCursorPos, OnChar/OnKeyDown/OnKeyUp callbacks, GetScreenScale).
