## schema

`pob-dump --compile` (crates/pob-dump/src/compile.rs) deserialises the whole dump into
`pob_gamedata::Data`. Every schema struct is `#[serde(deny_unknown_fields)]` or a hand-written
strict deserializer; an unknown key fails with its Lua path (e.g.
`data.skills.X.statMap.Y: unknown statMap entry key "flags"`). Every dump root must be typed
(`data::TYPED_ROOTS`, 78 roots), a stat-description scope (22), or listed in
`data::DYNAMIC_ROOTS` (35); any other root fails the compile. Result at the pin: **zero unknown
keys**; `data.bin` 39.7 MB; release runtime load (postcard decode + typed deserialise) 0.27 s.

The deserializer (`loader::TreeDeserializer`) presents each Lua table in the dump's JSON shape:
string keys, then the pseudo-members `$seq`, `$num` (canonical number text keys), `$keys`,
`$meta`. `$ref` is resolved transparently; `loader::shared` keeps one `Arc` per Lua table
(canonical path), so `data.gems[x].grantedEffect` *is* `data.skills[y]`, as in Lua. Ignored values
are not walked (`statMap._grantedEffect` is a back-reference).

**Typed roots** (fields: the census of the dump; see the schema files):
skills (`GrantedEffect`, `LevelTable`/`SkillLevel` with `EXTRA_KEYS`, `StatMap`/`StatMapEntry`/
`StatMapItem`, `SkillPart`), gems (`GemData`), gemForSkill (skill id → gem id), gemForBaseName
(lowercased name → gem id), skillStatMap, skillStatMapMeta (checked: one `__index` fn),
itemBases (`ItemBase` with `WeaponBase`/`ArmourBase`/`FlaskBase`/`TinctureBase`/`BaseReq`),
minions/spectres (`MinionData`; spectres share the minion `Arc`s), highPrecisionMods,
defaultHighPrecision, misc/characterConstants/monsterConstants/gameConstants (P1's generated
records), the monster tables, monsterVarietyLifeMult, mapLevel*Mult, totemLifeMult,
goldRespecPrices, maxJewelRadius, enemyIsBossTooltip, the 8 function members (`Data::fns`),
weaponTypeInfo, unarmedWeaponData (keys 0-6), nonDamagingAilment, the four ailment type lists,
jewelRadii, clusterJewels, keystones, uniques (texts), rares, itemMods (`AffixTable` per category,
`ItemMod`), masterMods (list), veiledMods, necropolisMods, uniqueMods, pantheons, bosses,
bossSkills, bossSkillsList, costs (with its `__index` alias as `Costs::by_resource`),
cursePriority, ConfigOptions (`ConfigOptionDef`), mapMods (`ModMapDefs`), CalcSections (kept as
`DataValue`, UI data), PearlSupports, GameVersions, ModCache (line → `{mods, extra}`), the
timeless scalars (`TimelessMeta`).

**Dynamic roots** (`Data::other`, resolve refs with `Data::resolve`): global, abyssNotableNames,
beastCraft, casterTagCrucibleUniques, clusterJewelInfoForNotable, crucible, enchantments,
enchantmentSource, essences, flavourText, foulbornMap, gemGrantedEffectIdForVaalGemId,
gemVaalGemIdForBaseGemId, gemsByGameId, itemBaseLists, itemBaseTypeList, itemTagSpecial,
itemTagSpecialExclusionPattern, minionTagCrucibleUniques, modScalability,

## modstore

`ModStore` per §5.3, except `parent: Field<Option<ModStoreRef>>` (CalcSetup.lua:689-692 reassigns
it). `conditions`/`multipliers` are fixed `Table`s: the only reassignments are `wipeTable` (same
table) and `specCopy` on freshly created stores (Common.lua:527-540), which ports as filling the
fresh, unaliased tables. The struct's `mods` storage is private to the MS-A files. The method
signatures are in `classes/mod_store.rs` (shared), `mod_db.rs` (`*_DB`), `mod_list.rs` (`*_List`)
and `eval_mod.rs`.
