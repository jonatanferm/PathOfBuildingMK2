## A. Decision: `ImageHandle::unload(&self)` stays; textures live until exit (§13 item 10)

Evidence: `ui_api.cpp:386-392` `l_imgHandleGC` and `:435-442` `l_imgHandleUnload` delete the
`r_shaderHnd_c`; `r_main.cpp:94-100` its destructor decrements `refCount` and calls
`AbortLoad` at 0; `r_main.cpp:1574-1583` `PurgeShaders` (end of `EndFrame`, `:1560`) frees
shaders with `refCount == 0 && status == DONE`.

So in SG a texture goes away when the Lua GC collects its last handle, at a nondeterministic time.
Rust drops are immediate. Releasing on drop would re-decode images every frame at PoB sites that
create a handle per draw (`ExtBuildListControl.lua:195` per listed build, `Tooltip.lua:508-511`
per influence tooltip draw). PoB never calls `Unload`, `IsValid`, `IsLoading` or
`SetLoadingPriority` (grep of `src/`). U3 therefore keeps the frozen `unload(&self)` and never
releases a texture: `Frame::releases` is always empty. `AbortLoad` is not modelled either.

Proposed §4.5 text:

```diff
-    /// UI-U0: clears the shared slot only; `Frame::releases` stays empty (textures live until exit). Open (U3 decides,
-    /// §13 item 10): `unload(&self, sg: &mut Sg)` dropping one registry reference, 0 => `Frame::releases` (CCR-0013 A2).
+    /// Clears the shared slot (`delete hnd; hnd = NULL`). Textures live until exit, so `Frame::releases` stays empty:
+    /// SG frees a texture when the Lua GC collects its last handle, which has no deterministic equivalent (CCR-0023 A).
     pub fn unload(&self);
```

§13 item 10 becomes: "**Closed** (CCR-0023 A): `unload(&self)` kept; textures are never released."

## B. Mips: SG uses stb_image_resize (sRGB, Mitchell), not a gamma box filter

Evidence: `r_texture.cpp:433-461` `BuildMipSet`. When mips are generated, each level is
`stbir_resize_uint8_srgb_edgemode(prev, ..., comp, comp == 4 ? 3 : STBIR_ALPHA_CHANNEL_NONE, 0,
STBIR_EDGE_CLAMP)` of the previous level. The `gli::generate_mipmaps(newTex, FILTER_LINEAR)` call
is commented out (`:459`). The stb version is `dep/stb/stb_image_resize.h` v0.97, whose default
downsampling filter is Mitchell (`:432-434`). It works in linear light through its sRGB tables and
premultiplies alpha with `STBIR_ALPHA_EPSILON` (2^-80). Levels follow gli: `floor(log2(max(w,h)))+1`
levels with extents `max(1, e >> level)`.

U3 ports that subset of stb_image_resize (`image.rs` `mod stbir`: the downsampling path,
coefficient normalisation, sRGB decode table, `stbir__linear_to_srgb_uchar`, the encode rounding).
The port matches goldens produced from SG's own header with gcc and clang (`-ffp-contract=off`,
with -O0, -O2 and FMA builds giving identical output), byte for byte on 12 synthetic images: 8x8,
16x4, 5x3, 7x1, 1x9, 33x17, 64x64, 100x37, 3x3, 2x2, 257x3 and 12x40, as RGBA and as RGB. The
generator is reproduced at the end of this file. PoB itself never passes `"MIPMAP"`
(`PassiveTree.lua:263`, `:308` have it commented out).

```diff
-- MIPMAP levels use a 2×2 box filter on raw (gamma) values. (UI-U0 still uses the moved sRGB-correct filter; U3 switches it, CCR-0013 D.)
+- MIPMAP levels are `BuildMipSet`'s (r_texture.cpp:433-461 @3b1a346): each level is `stbir_resize_uint8_srgb_edgemode`
+  (stb_image_resize v0.97: Mitchell, sRGB-linear, alpha-premultiplied when the image has 4 channels, clamped edges) of the
+  previous one. Ported bit-exactly in `pob-sg/src/image.rs` (CCR-0023 B).
```

AMENDMENTS A4, last paragraph:

```diff
-mip generation is still the moved sRGB-correct filter (ui doc §4.5 asks for a gamma box filter;
-U3 switches it).
+mip generation is SG's `stbir_resize_uint8_srgb_edgemode` chain, ported by U3 (CCR-0023 B; the
+gamma box filter §4.5 used to ask for was wrong).
```

## C. Dedup, re-registration, empty path (§4.5 "U3 verifies this against RegisterShader")

Evidence: `r_main.cpp:1585-1614` `RegisterShader` matches an existing shader when
`StringHash(name, 0xFFFF)` is equal, `_stricmp` is equal and `tex->flags` are equal. `StringHash`
(`common.cpp:345-353`) is **case-sensitive**, so the case-insensitive `_stricmp` only matters when
two masked 16-bit hashes collide. Whether they do depends on the absolute `scriptWorkDir` prefix
(`ui_api.cpp:402-405` joins it before registering). On a match, `ForceLoad` (`r_texture.cpp:376-384`)
loads again, synchronously, any texture whose `fileWidth` is still 0: a failed load, or an ASYNC
load that has not parsed its header yet. `RegisterShader("")` returns NULL, but `imgHandleLoad`
always passes `scriptWorkDir / fileName`, and that is non-empty in PoB.

The port keys on `(path with '\' -> '/', flags)` and compares exactly (no hash-collision
emulation). The UI-U0 code folded case, which was wrong. Paths are not joined with the script dir,
so an absolute path that names the same file as a relative one is a different texture; PoB passes
only relative paths. Re-registration runs `ForceLoad`. `Load("")` gives a valid handle on a failed
texture: `ImageSize() == (0,0)` and `IsLoading() == true` (the UI-U0 code cleared the handle).

```diff
-- Registration is deduplicated by `(path, flags)`. U3 verifies this against `RegisterShader` at `r_main.cpp:1366`.
+- Registration is deduplicated by `(path, flags)` with `\` read as `/`, compared exactly (SG: case-sensitive 16-bit
+  `StringHash` + `_stricmp` + flags, r_main.cpp:1585-1614 @3b1a346; hash collisions between case variants are not
+  emulated). Re-registering a texture whose size is still unknown loads it again synchronously (`ForceLoad`), so a
+  failed load is retried on every `Load`. `Load("")` names the script directory: a valid handle on a failed texture.
```

## D. Smaller behaviour points (applied in `image.rs`)

- `IsLoading`, `ImageSize` and `SetLoadingPriority` on an unloaded handle raise
  `imgHandle:<Method>(): image handle has no image loaded` (`GetImgHandle(..., true)`,
  `ui_api.cpp:375-384`). UI-U0's `set_loading_priority` silently ignored it, and its `is_loading`
  reported the `ImageSize` text. `Unload` and `IsValid` accept an unloaded handle.
- A failed load keeps the size the format's size callback set before the error, so a corrupt file
  with a readable header has its header size. The loaders' `read_size` returns `Some` exactly where
  SG's per-format loader calls the callback: PNG/JPEG after `stbi_info`, WebP after `WebPGetInfo`,
  TGA after a header without a colour map, GIF/DDS never (they are not decoded).
- Format detection is `LoaderForFile`'s (`core_image.cpp:93-141`): `.dds`, `.dds.zst` and `.webp` by
  (case-sensitive) extension, then by magic bytes, TGA by header bytes. The UI-U0 code chose TGA by
  extension. PNG loads as RGB/RGBA (1/3 → 3 channels, 2/4 → 4), JPEG as L8/RGB and WebP as RGBA.
  16-bit PNG channels are reduced with `>> 8` (`stbi__convert_16_to_8`). Sides of 32768 px or more
  fail (`CopyRaw`).
- `ImageRegistry::take_uploads` polls the loader first. That is SG's `PumpShaders` in `EndFrame`
  (`r_main.cpp:1150-1159`, `:1267`), so an ASYNC texture that completes during a frame is drawn
  in that frame.
- Unknown flag: SG deletes the old handle before it validates the flags (`ui_api.cpp:406-427`).
  `ImageFlags::from_lua` runs before `ImageRegistry::load`, so the U8 bridge calls `unload` on the
  handle before it raises the error if it wants SG's state afterwards. Non-string flag arguments
  are skipped by SG (`continue`); the bridge leaves them out.

Surface addition (U3-owned file, no existing signature changed):

```diff
 pub fn read_image_size(bytes: &[u8], name: &str) -> Option<(u32, u32)>;
+/// read_image_size over a reader (the native loader reads only the header from disk).
+pub fn read_image_size_from<R: std::io::BufRead + std::io::Seek>(r: R, name: &str) -> Option<(u32, u32)>;
```

## F. Decoders (DIVERGENCE, measured)

PNG, JPEG and WebP decode through the `image` crate (`image 0.25.10`, which uses png, zune-jpeg and
image-webp), not through stb_image v2.26 and libwebp. U3 compared all 131 images under
`src/Assets` and `src/TreeData/3_27` against stb_image v2.26 (SG's `dep/stb`) and libwebp 1.6
`WebPDecodeRGBA`, after the same channel expansion. All 99 PNGs and both WebPs are byte-identical.
The 30 JPEGs differ by at most 4 levels per channel. More than 2 levels differ on at most 0.1% of
a file's pixels: the two `skills*-3.jpg` sprite sheets reach 0.097%, `ascendancy-background-3.jpg`
0.021%, and the `Assets/ascendants/*.jpeg` at most 0.007%. Inside T6's ±2/255-on-99.5% budget.
All 769 images of every tree version decode (ignored test `pob_all_tree_versions_decode`).
GIF and DDS are detected but not decoded (PoB ships none).

## G. Notes for other units

- **U6** (backend, raster): `Frame::releases` is always empty (A). A `TexId` bound before its
  upload (pending ASYNC) must sample `@black`, as `r_tex_c::Bind` does at `r_texture.cpp:340-347`.
- **U7** (web host): `WebLoader::new(base_url)` / `with_vfs(base_url, vfs)`, `vfs()`,
  `insert(path, bytes)`, and `prefetch(&[paths]).await`, which fetches concurrently into the VFS and
  is awaited before `on_init` and before a tree version switch. A sync load that misses the VFS
  fails; an ASYNC miss is fetched lazily, and at most one image is decoded per `poll`. `ImageSize` of
  an unfetched ASYNC image is `(0,0)` (PoB re-queries a zero width, PassiveTreeView.lua:548-550,
  :1290-1295).
- **U8** (bridge): the unknown-flag order in D; the error texts in D.

## Golden generator (B)

`gold.c`, compiled against SG's `dep/stb/stb_image_resize.h` with `gcc -O0 -ffp-contract=off`. It
prints the `MIP_GOLDENS` rows of `image.rs` (FNV-1a 64 over all levels, level 0 included):

```c
#define STB_IMAGE_RESIZE_IMPLEMENTATION
#include "stb_image_resize.h"
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
static uint64_t fnv_feed(uint64_t h, const unsigned char* p, size_t n) {
    for (size_t i = 0; i < n; i++) { h ^= p[i]; h *= 0x100000001b3ULL; } return h; }
static void synth(unsigned char* out, int w, int h, uint64_t seed) {
    uint64_t s = seed;
    for (int i = 0; i < w * h; i++) {
        for (int c = 0; c < 4; c++) { s = s * 6364136223846793005ULL + 1442695040888963407ULL;
                                      out[i * 4 + c] = (unsigned char)(s >> 33); }
        if (i % 7 == 3) out[i * 4 + 3] = 0;
    }
}
static int levels_of(int w, int h) { int m = w > h ? w : h; int n = 0; while (m) { n++; m >>= 1; } return n; }
static uint64_t chain(const unsigned char* base, int w, int h, int comp) {
    int alpha = comp == 4 ? 3 : STBIR_ALPHA_CHANNEL_NONE;
    unsigned char* prev = malloc((size_t)w * h * comp);
    if (comp == 4) memcpy(prev, base, (size_t)w * h * 4);
    else for (int i = 0; i < w * h; i++) memcpy(prev + i * 3, base + i * 4, 3);
    uint64_t hsh = fnv_feed(0xcbf29ce484222325ULL, prev, (size_t)w * h * comp);
    for (int l = 1; l < levels_of(w, h); l++) {
        int sw = w >> (l - 1); if (sw < 1) sw = 1;  int sh = h >> (l - 1); if (sh < 1) sh = 1;
        int dw = w >> l; if (dw < 1) dw = 1;        int dh = h >> l; if (dh < 1) dh = 1;
        unsigned char* dst = malloc((size_t)dw * dh * comp);
        stbir_resize_uint8_srgb_edgemode(prev, sw, sh, sw * comp, dst, dw, dh, dw * comp, comp, alpha, 0,
                                         STBIR_EDGE_CLAMP);
        hsh = fnv_feed(hsh, dst, (size_t)dw * dh * comp); free(prev); prev = dst;
    }
    free(prev); return hsh;
}
int main(void) {
    int cases[][3] = { {8, 8, 1}, {16, 4, 2}, {5, 3, 3}, {7, 1, 4}, {1, 9, 5}, {33, 17, 6},
                       {64, 64, 7}, {100, 37, 8}, {3, 3, 9}, {2, 2, 10}, {257, 3, 11}, {12, 40, 12} };
    for (size_t i = 0; i < sizeof cases / sizeof cases[0]; i++) {
        int w = cases[i][0], h = cases[i][1]; uint64_t seed = (uint64_t)cases[i][2];
        unsigned char* base = malloc((size_t)w * h * 4); synth(base, w, h, seed);
        printf("(%d, %d, %llu, 0x%016llx, 0x%016llx),\n", w, h, (unsigned long long)seed,
               (unsigned long long)chain(base, w, h, 4), (unsigned long long)chain(base, w, h, 3));
        free(base);
    }
    return 0;
}
```
